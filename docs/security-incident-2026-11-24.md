## 载荷和工具做了什么

### 批量网页注入

`inj2.pl`、`inj3.pl`、`_inj_new.sh/.py/.pl` 会扫描网页根目录，匹配 php/html/tpl/ejs/vue/jsp 等扩展名，在 `<head>` 后插入来自 `188-96A2175A.jiaoyang677.sbs` 的 `/lj/e.js`。`_inj_new.sh` 会解析 Nginx vhost 的 root 并选择 Perl／Python执行注入。`rs_verify_new_sites_sh.sh` 检查各 vhost 的真实页面是否已经带该域名。

**实际已证明注入的文件**：前轮保存的 PayIncus `client/dist/user/index.html`、`client/dist/admin/index.html`，以及本轮保存的 Nginx 默认页面。不能把工具能扫描的所有文件都称为已实际改写。

当前载荷不能代替历史载荷，也没有执行后续漏洞链，不能确认哪台设备被攻破。未发现 e.js 本体直接读取 document.cookie／输入密码的代码，不据此排除其远端后续载荷行为或页面 URL 外传。历史 CSP 效果与真实访问者影响另需调查，不能凭当前响应宣布全部访问者安全。
